# ShotStudio — Domain Context

ShotStudio is a single-tenant, one-time-pay tool that turns three raw mobile screenshots into a polished four-image App Store screenshot set. The codebase is small enough to share one glossary; section headers below indicate the bounded context each term belongs to.

## Language

### Generation context

- **Generation** — A single end-to-end job that produces one Set of four Shots from one user's inputs. _Avoid_ "render", "job", "run".
- **Set** — The four-Shot deliverable returned by one Generation. _Avoid_ "screenshot set", "image set", "output", "bundle", "pack" (Pack means a Credit Pack).
- **Shot** — One of the four images in a Set, generated by the AI; each has a Shot Role. _Avoid_ "image", "panel", "frame", "output image".
- **Shot Role** — One of `title`, `hero_feature`, `differentiator`, `another_feature`; determines the prompt and which Reference Screenshot (if any) is used. _Avoid_ "shot type", "slot".
- **Title Shot** — The Shot with role `title`; has no Reference Screenshot and uses the Tagline as its hero headline. _Avoid_ "hero shot" (overloaded).
- **Reference Screenshot** — A user-uploaded raw mobile screenshot fed to the model as image-to-image input for one non-Title Shot. _Avoid_ "input image", "source image", "uploaded screenshot".
- **Tagline** — A 5–10 word user-supplied headline rendered on the Title Shot. _Avoid_ "headline", "subtitle".
- **Style Preset** — One of four named visual styles (`soft_bright`, `dark_premium`, `clean_minimal`, `bold_playful`) bundling palette, typography and tone modifier. _Avoid_ "theme", "style", "look".
- **Category** — The app's App Store category; maps to a default Style Preset that the user can override. _Avoid_ "vertical", "genre".
- **Pending Generation** — A Generation row whose `status = 'pending'` — Credit already debited, work in flight. _Avoid_ "in-progress generation", "running job".

### Billing context

- **Credit** — The unit of account. 1 Credit = 1 Generation. Credits never expire and are not refundable except via failed-Generation Refund. _Avoid_ "token", "shot credit".
- **Credit Pack** — A purchasable bundle of Credits at a fixed price (`starter`, `growth`, `studio`). _Avoid_ "plan", "tier", "package" (the type is named `CreditPackage`, but in conversation prefer "pack" — "package" collides with the pnpm sense).
- **Transaction** — A row in the Credits ledger recording a Credit movement of type `purchase`, `usage`, or `refund`. _Avoid_ "ledger entry", "credit event".
- **Grant** — The Billing operation that credits a Pack's Credits to a User after a successful Stripe checkout; idempotent on `stripePaymentId`. _Avoid_ "issue", "top-up".
- **Debit** — The atomic operation that decrements one Credit and inserts a Pending Generation in the same DB transaction (`debitAndStartGeneration`). _Avoid_ "charge", "spend", "consume".
- **Refund** — The operation that re-credits one Credit when a Generation fails in-route. _Avoid_ "reverse", "rollback".
- **Checkout Session** — The Stripe-hosted payment page created by `/api/checkout`; its `id` is reused as the `stripePaymentId` on the resulting Grant. _Avoid_ "payment session".

### Identity context

- **User** — An authenticated Clerk identity with a mirrored `users` row holding the Credit balance. Single-tenant: no orgs, no teams. _Avoid_ "account", "customer" (Stripe Customer is a different thing).
- **JIT User Sync** — The `ensureUser` upsert called on every authenticated entry point so a User row exists before any Billing or Generation work; closes the Clerk-vs-Stripe webhook race. _Avoid_ "user provisioning", "user bootstrap".
- **User Anonymization** — On Clerk `user.deleted`, replacing email with `deleted+<id>@anonymized.local` and nulling `stripeCustomerId` instead of deleting the row, to preserve the financial audit trail. _Avoid_ "user deletion", "user purge".

## Relationships

- A **User** has a Credit balance (integer) and a history of **Transactions**.
- A **User** has many **Generations**; each Generation belongs to exactly one User.
- A **Generation** produces one **Set** of four **Shots**; each Shot has one **Shot Role**.
- A **Generation** is configured by exactly one **Style Preset** and one **Category**; Category determines the default Style Preset.
- A non-Title Shot consumes exactly one **Reference Screenshot**; the **Title Shot** consumes the **Tagline** instead.
- A **Debit** atomically creates a Pending Generation and writes a `usage` Transaction.
- A successful Generation transitions to `complete`; a failure transitions to `failed` and triggers an in-route **Refund** which writes a `refund` Transaction.
- A **Grant** writes a `purchase` Transaction whose `stripePaymentId` equals the **Checkout Session** id; this provides webhook idempotency.
- A **Credit Pack** maps to a Stripe Price; on `checkout.session.completed` the Pack's `credits` are Granted to the User identified by `metadata.userId`.

## Example dialogue

> **PM:** "Mira just paid for the Growth pack but her balance still shows 0 — what's going on?"
>
> **Eng:** "Stripe webhook delivery hasn't landed yet. The Checkout Session completed on Stripe's side, but our `checkout.session.completed` handler is what calls `grant`, and that's what bumps her Credit balance. If she refreshes in a few seconds it should be there — and the Grant is idempotent on the session id, so even if Stripe retries we won't double-credit her. If it's been minutes, look in the Stripe dashboard for the event id and check the webhook logs."
>
> **PM:** "Got it. And if her Generation fails halfway through?"
>
> **Eng:** "The route catches the error, marks the Generation `failed`, and Refunds the Credit inline before responding — so her balance ends up where it started."

## Flagged ambiguities

- **"Screenshot"** — Used in two distinct senses across the codebase: a **Reference Screenshot** (raw user-uploaded mobile screenshot, _input_) versus an App Store screenshot in the colloquial / marketing sense (the _output_, which we call a **Shot**). UI copy in `wizard.tsx` and `how-it-works.tsx` says "screenshot" for input; FAQ and hero copy say "screenshot" for output. Within code, prefer "Reference Screenshot" for input and "Shot" for output.
- **"Set"** — Marketing copy and Pack pricing UI use "set" (`pluralize(p.credits, "set")`) as a synonym for "Credit", e.g. "10 sets". Internally, a Set is the *output* of a Generation, not a unit of account. The 1:1 mapping (1 Credit → 1 Generation → 1 Set) makes the slippage harmless, but copy that says "Buy 4 sets" really means "Buy 4 Credits". Worth keeping the data model wording (`credits`) distinct from the user-facing wording ("sets") in conversation.
- **"Hero"** — Overloaded. In Marketing it means the landing-page hero section. In Generation it means the `hero_feature` Shot Role (Shot 2 in the Set). The Title Shot is *not* the hero feature — it is the title.
- **"Generation"** — Used for (a) the verb/act of generating (`generate()`), (b) the DB row (`generations` table), and (c) loosely for the Set it produces. Prefer **Generation** for the row/job and **Set** for the deliverable.
- **"Package" vs "Pack"** — The TypeScript type is `CreditPackage`, the variable is `pack`, the marketing UI says "pack". Prefer "Credit Pack" in conversation; "package" collides with pnpm's sense. The code naming asymmetry is not worth refactoring but is worth knowing.
- **"Customer"** — Stripe uses "Customer" for its own object; we don't model Customers in our schema (only `stripeCustomerId` on the User). Don't say "customer" when you mean "User".
